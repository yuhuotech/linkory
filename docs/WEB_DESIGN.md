# 网页版（my.linkory.cn）需求与技术设计

状态：开发中（第 1 阶段）。文档随实现更新。

## 1. 目标与范围

在现有 Flutter 工程里增加 Web 平台，让用户在浏览器中使用连信，界面与交互和桌面客户端基本一致。**网页版就是账号下的又一台设备**：同一服务器、同一用户登录后，网页与各端客户端互相出现、互发消息与文件，服务端不区分对待（仅设备类型为 `web`）。

不做：推送通道（页面关闭后收不到消息）、局域网直连（浏览器不能监听端口）、托盘/开机启动/应用内更新（网页端隐藏）、SEO/落地页。

## 2. 设备身份（核心需求）

规则：**同一个浏览器（同一浏览器配置文件）= 同一台设备；不同浏览器/配置文件/无痕窗口 = 不同设备；浏览器升级不改变身份。**

- 不用 User-Agent 或浏览器指纹（升级、扩展、隐私设置都会让它变化，会造成设备数量失控）。
- 首次登录时由客户端生成 Ed25519 密钥并取得服务端分配的 `device_id`，两者持久保存在该站点的浏览器存储（localStorage，经 shared_preferences）。之后登录沿用同一个 `device_id`（与桌面端逻辑一致：仅限同服务器 + 同账号）。退出登录不删除设备身份。
- 请求 `navigator.storage.persist()` 降低存储被清理的概率。无法完全避免：用户清除站点数据、Safari 对长期未访问站点清理（约 7 天，PWA 安装后豁免）、无痕窗口都会变成新设备。
- 因此服务端必须兜底，防止设备数失控：
  - 每个账号最多 10 个网页设备；超过时自动吊销**最久未在线**且当前离线的网页设备（而不是拒绝登录）。
  - 网页设备超过 30 天未在线自动吊销（并入每小时的清理任务）。
  - 用户仍可在「设备」页手动重命名/删除。
- 设备名由浏览器与系统组成，如 `Chrome · macOS`，可由用户改名。

### 同一浏览器多个标签页
服务端规定“一台设备同一时刻只有一条连接，新连接顶掉旧连接”，多个标签页会互相顶替并无限重连。所以网页端采用 WhatsApp Web 的方式：用 Web Locks API 取得 `linkory-session` 锁的标签页才是“活动标签页”；其他标签页显示“连信已在另一个标签页打开”，点击「在此使用」会抢占锁，原标签页随即变为只读提示页。

## 3. 架构

- 复用同一套 Flutter 代码（`store.dart`、UI、测试），平台差异通过条件导入隔离，原生实现与网页实现各一份：
  | 能力 | 原生 | 网页 |
  |---|---|---|
  | 凭据/设备身份 | 钥匙串 + 偏好 | localStorage（经 `Secrets`，第 6 节说明风险） |
  | 新消息通知 | 系统通知/角标 | 浏览器 Notification + 标签页标题未读数；仅页面开着时有效 |
  | 设备名/类型 | 主机名/平台 | 浏览器 + 系统；类型 `web` |
  | 文件发送 | 本地路径流式读取 | 文件选择/拖拽 → `fetch` 上传（第 2 阶段） |
  | 文件接收 | 写入下载目录 | 浏览器下载（第 2 阶段） |
  | 局域网直连、托盘、更新、开机启动 | 有 | 无（界面隐藏） |
- **同源部署**：服务端新增 `LINKORY_WEB_DIR`，设置后在未匹配的路径上托管网页静态文件（带 CSP 等安全头）。浏览器始终访问页面所在源，无需 CORS，WebSocket 的 Origin 校验天然通过。`my.linkory.cn` 与现有域名指向同一个服务端进程，账号互通。
- 网页端服务器地址固定为 `Uri.base.origin`，登录页不显示地址输入。
- 构建：`flutter build web --release --no-web-resources-cdn`（CanvasKit 随包发布，不依赖 gstatic，国内可用），并随包内置中文字体（否则中文会回退到 gstatic 字体而显示方块）。

## 4. 服务端改动

1. 设备类型新增 `web`（`auth.validTypes`）。
2. 网页设备数量上限 + 久未在线自动吊销（第 2 节）。
3. `LINKORY_WEB_DIR` 静态托管 + 安全头（CSP：`default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; connect-src 'self' wss: ; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; font-src 'self' data:`，`X-Content-Type-Options`、`Referrer-Policy`、`frame-ancestors 'none'`）。
4. 协议无变化。

## 5. 分阶段

1. **第 1 阶段（本次）**：Web 平台可运行；登录/注册、设备列表、文字消息、未读与浏览器通知、多标签页互斥、服务端改动、部署。文件功能在网页端暂时禁用并提示；若有设备向网页设备发文件，网页端自动拒绝并说明原因（不让发送方卡在等待）。
2. 第 2 阶段：文件发送（`fetch` 上传，设大小上限提示）与接收（浏览器下载；Chromium 用“另存为”接口流式写盘，其他浏览器先入内存，设上限）。
3. 第 3 阶段：PWA 安装、令牌改为 httpOnly Cookie、（可选）WebRTC 直连。

## 6. 安全与已知限制

- 令牌与密钥种子在 localStorage 中，页面脚本被注入时可被读取；以严格 CSP、同源托管、不引入第三方脚本来降低风险；第 3 阶段改 httpOnly Cookie + CSRF 防护。
- 关闭网页后不会收到消息与通知（无推送通道）；重新打开时离线消息会补发（默认保留 30 天）。
- 网页与其他设备之间的文件一律走服务器中转。
- 清除站点数据 = 新设备，旧设备由自动清理回收。
